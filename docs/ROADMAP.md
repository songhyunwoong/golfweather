# 골프날씨 개발 단계

[개발 계획서](PLAN.md) 10장의 로드맵을 4개 단계로 다시 묶었다. 각 단계는 그 자체로 쓸 수 있는 결과물로 끝난다.

| 단계 | 이름 | 기간 | 끝났을 때 사용자가 할 수 있는 것 |
|---|---|---|---|
| **1** | **MVP: 골프장 예보** | 5주 | 골프장을 초성으로 찾아 7일 예보를 모델별로 보고, 모델 신뢰도를 확인한다 |
| 2 | 지도 날씨 | 4주 | Ventusky처럼 지도에서 강수·기온·바람을 시간대별로 본다 |
| 3 | 신뢰도 자동화 | 3주 | 매일 갱신되는 지역별 신뢰도와 성적 가중 블렌드, 15일 예보를 본다 |
| 4 | 앱과 알림 | 3주 | 앱을 설치하고, 등록한 라운드의 예보가 바뀌면 알림을 받는다 |

이후 확장(홀 방위 기반 맞바람, 낙뢰·미세먼지, 지점별 보정, 해외 골프장)은 4단계 뒤에 정한다.

## 단계별 범위

### 1단계. MVP: 골프장 예보 (5주)

상세는 [MVP 계획서](MVP.md).

- 골프장 검색(초성·별칭)
- 골프장 상세: 라운드 요약, 일별 7일, 시간별 1시간/3시간
- 모델 선택: ICON, ECMWF IFS, ECMWF AIFS, GFS, UKMO, 기상청 단기예보, 블렌드
- 모델 신뢰도 배지(2026년 8~11월 검증 결과 기반, 고정값)
- 골프장 위치 지도(마커만)
- 최근 본 골프장·즐겨찾기(기기 저장)

### 2단계. 지도 날씨 (4주)

- 강수·기온·바람 레이어, 시간 슬라이더와 재생
- 바람 파티클 애니메이션
- 모델별 레이어 전환(ICON, ECMWF, GFS)
- 지도에서 골프장을 눌러 상세로 이동
- 기상청 레이더 실황(선택)

**진행 상황 (2026-11-12)**

| 항목 | 상태 |
|---|---|
| 강수·기온·바람 레이어, 시간 슬라이더와 재생 | 완료 (7일. 1시간/3시간 전환, 1시간 간격은 3일까지) |
| 바람 표시 | 화살표와 풍속 숫자(m/s), 풍속 단계별 색. 흐름 애니메이션은 세기를 읽기 어려워 뺌 |
| 모델 전환 (ICON, ECMWF, GFS) | 완료 |
| 지도에서 골프장을 눌러 상세로 이동, 상세에서 지도로 이동 | 완료 |
| 지도를 눌러 그 지점의 값 보기 | 완료 |
| VWorld 위성 배경 | 전환 버튼 추가. 저장소 시크릿 `VWORLD_API_KEY`가 있으면 버튼이 나오고, 불러오지 못하면 기본 지도로 돌아감. 개발 환경에서 VWorld에 접속할 수 없어 실제 화면은 확인하지 못함 |
| 기상청 레이더 실황 | 미착수 |
| 지도에서 초성 검색 | 완료 |

만든 방식은 계획과 다르다. 지도 타일을 만들지 않고, 한반도 영역(124~132°E, 32.5~39°N)을 0.1° 격자로 다시 계산해 변수마다 PNG 한 장에 담는다(`pipeline/build_maps.py`). 모델당 약 2.3 MB이고, 색칠과 바람 화살표는 브라우저에서 그린다. 생성에 약 2분이 걸려 예보 갱신 때 함께 돈다.

### 3단계. 신뢰도 자동화 (3주)

- 기상청 ASOS/AWS 실측 수집, 매일 자동 검증
- 권역 × 모델 × 리드타임 신뢰도(최근 90일)로 배지 교체
- 성적 가중 블렌드, "오늘 예보의 확실성"
- 8~15일 확장 예보(참고용 표시)
- 기상청 단기예보를 같은 방식으로 검증해 비교에 포함
- 신뢰도 성적표 화면

**진행 상황 (2026-11-12)**

| 항목 | 상태 |
|---|---|
| 기상청 실측 수집, 매일 자동 검증 | 완료 (`pipeline/verify.py`, `.github/workflows/verify.yml`, 매일 04:40) |
| 권역 × 모델 × 리드타임 신뢰도(최근 90일)로 배지 교체 | 완료. 지역 표본이 적으면 전국 값 사용 |
| "오늘 예보의 확실성" | 완료 (라운드 요약에 높음·보통·낮음) |
| 신뢰도 성적표 화면 | 완료 (안내 화면, 지역 선택) |
| 블렌드 검증 | 완료 (앱과 같은 규칙으로 계산해 함께 채점) |
| 성적 가중 블렌드 | 완료. 기온·바람은 예보 기간별 치우침 보정 + 1/MAE² 가중(5모델, 최근 90일 전국 성적, 매일 갱신). 강수는 실험에서 가중이 낫지 않아 중앙값 유지 ([실험](../research/blend-weights/)) |
| 8~15일 확장 예보 | 완료 (15일까지 표시, 8일 이후는 참고용으로 흐리게) |
| 기상청 단기예보 검증 | 미착수. 과거 예보 보관부터 필요 |

만든 방식은 계획과 조금 다르다. 보관한 예보 JSON을 쓰지 않고, Open-Meteo 오픈데이터에 남아 있는 과거 실행(00·12 UTC)을 관측소 위치에서 다시 읽어 채점한다. 그래서 보관 기간과 상관없이 과거 90일을 바로 소급할 수 있었다. 매일 최근 16일 초기화분을 다시 채점해, 관측이 채워진 리드타임만큼 통계가 늘어난다. 결과는 `data/verification/daily/`에 날짜별로 쌓인다.

관측은 기상청 API허브의 지상관측 시간자료(49개 지점 중 자료가 있는 지점)이고, 강수는 일 누적값의 차이로 12시간 합계를 구한다.

### 4단계. 앱과 알림 (3주)

- 모바일 앱(Expo 또는 PWA 래핑), 스토어 출시
- 계정과 즐겨찾기 동기화
- 라운드 등록, 예보 변화 알림(D-3, D-1, 당일 아침)
- "실제 날씨 어땠나요" 피드백

선행 조건: Open-Meteo 상업 구독, 개인정보처리방침, 위치정보 처리 방식 결정.

## 단계를 이렇게 나눈 이유

- **검색과 예보가 먼저다.** 이 앱의 핵심 가치는 "골프장 이름으로 바로 예보를 본다"이고, 지도 날씨 레이어 없이도 성립한다.
- **지도 날씨는 가장 무겁다.** 타일 생성 파이프라인과 WebGL 작업이 필요해서 MVP에 넣으면 출시가 두 배로 늦어진다.
- **신뢰도는 고정값으로 시작할 수 있다.** 이미 3개월 검증 결과가 있어서 MVP는 그 값을 그대로 보여주고, 자동 갱신은 3단계로 미룬다.
- **계정이 필요한 기능은 마지막이다.** 알림과 동기화는 서버·개인정보·스토어 심사가 따라오므로 앱 출시와 묶었다.
