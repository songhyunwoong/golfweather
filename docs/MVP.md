# 골프날씨 MVP 계획서 (1단계)

| 항목 | 내용 |
|---|---|
| 목표 | 골프장을 초성으로 찾아 7일 예보를 모델별로 보고, 모델 신뢰도를 확인한다 |
| 형태 | 모바일 우선 웹(PWA). 설치·로그인 없음 |
| 용도 | 우선 개인 사용. 공개 출시는 그 뒤에 결정 |
| 기간 | 5주 |
| 관련 문서 | [개발 단계](ROADMAP.md) · [개발 계획서](PLAN.md) · [모델 검증](../research/model-verification/) · [골프장 DB](../data/golf-courses/) |

## 1. 범위

### 넣는 것

| # | 기능 | 설명 |
|---|---|---|
| F1 | 골프장 검색 | 초성(`ㅂㅇㅋㄹㅋ`), 이름 일부, 별칭·옛 이름, 영문. 기기 안에서 검색 |
| F2 | 라운드 요약 | 고른 날짜와 티업 시각부터 5시간의 강수 합계, 바람(평균·돌풍), 기온 범위, 체감온도 |
| F3 | 일별 7일 | 날씨 아이콘, 최고·최저 기온, 강수량, 최대 풍속. ICON은 7일, 나머지는 7일까지만 표시 |
| F4 | 시간별 예보 | 1시간/3시간 전환. 기온선, 강수 막대, 바람 화살표. 원자료가 3시간인 구간은 표시 |
| F5 | 모델 선택 | ICON(기본), ECMWF IFS, ECMWF AIFS, GFS, UKMO, 기상청 단기예보, 블렌드 |
| F6 | 모델 신뢰도 배지 | 모델 × 리드타임 별점(1~5). 누르면 근거 수치와 검증 기간 표시 |
| F7 | 모델 비교 | 같은 날짜에 모델들의 강수·기온을 한 화면에서 비교. 비 예보 모델 수("5개 중 4개 비 없음") |
| F8 | 위치 지도 | 골프장 위치 마커와 길찾기 링크(네이버·카카오·티맵) |
| F9 | 최근·즐겨찾기 | 기기에만 저장 |
| F10 | 예보 보관 | 생성한 예보 JSON을 날짜별로 보관. 화면에는 없지만 3단계 검증의 재료 |

### 넣지 않는 것 (이후 단계)

| 지역별·자동 갱신 신뢰도 | 3 | 실측 수집 파이프라인 필요. MVP는 고정값 |

| 라운드 적합도 지수 | 3 | 가중치를 검증할 피드백이 없음. MVP는 수치를 그대로 보여줌 |

## 2. 사용자 흐름

1. 첫 화면에서 검색창에 `ㅂㅇㅋ`를 입력한다. 입력하는 동안 결과가 나온다.
2. "베어크리크골프클럽 · 포천"을 누른다.
3. 상세 화면 맨 위에서 토요일, 티업 07:00의 라운드 요약을 본다.
4. 모델을 ICON에서 ECMWF로 바꿔 본다. 배지가 "D+3 ★★★★"로 바뀐다.
5. "모델 비교"를 눌러 토요일 오전 강수를 모델별로 본다.
6. 별표를 눌러 즐겨찾기에 넣는다. 다음에 열면 첫 화면에 나온다.

## 3. 화면

### 3.1 홈

- 검색창(자리 표시 문구: "골프장 이름 또는 초성, 예: ㅂㅇㅋㄹㅋ")
- 즐겨찾기 골프장 카드: 이번 주 토·일 요약(날씨 아이콘, 기온, 강수)
- 최근 본 골프장

### 3.2 검색 결과

- 이름, 지역, 일치한 부분 강조
- 결과가 없으면: "찾는 골프장이 없나요?" 제보 링크(메일 주소 표시)

### 3.3 골프장 상세

| 영역 | 내용 |
|---|---|
| 머리 | 이름, 지역, 즐겨찾기, 길찾기 |
| 모델 줄 | 모델 선택기, 신뢰도 배지, 예보 생성 시각("ICON 11/11 09시 실행") |
| 라운드 요약 | 날짜·티업 시각 선택(기본: 가장 가까운 토요일 07:00), 5시간 요약, 비 예보 모델 수 |
| 일별 | 7일 가로 스크롤 |
| 시간별 | 1시간/3시간 전환, 그래프와 표 |
| 모델 비교 | 고른 날짜의 모델별 강수·기온 |
| 위치 | 지도 마커, 주소, 고도 |
| 꼬리 | 자료 출처, 면책 문구 |

### 3.4 정보

- 모델 설명, 신뢰도 산출 방법, 자료 출처, 문의 주소

## 4. 데이터

### 4.1 골프장

- [골프장 DB](../data/golf-courses/) `courses.json`을 그대로 쓴다. 현재 v2(495곳, 검수 완료).
- 앱에는 검색용 축약본(id, 이름, 별칭, 초성, 지역, 좌표)을 따로 만들어 싣는다. 약 60 KB(gzip).
- **MVP 출시 조건**: 검수 표시가 붙은 233곳과 위치를 못 정한 인허가 48건의 검수가 끝나야 한다.

### 4.2 예보

| 모델 | 원천 | 갱신 | 표시 기간 |
|---|---|---|---|
| DWD ICON | Open-Meteo 오픈데이터(AWS) | 6시간 | 7일 |
| ECMWF IFS 9km | Open-Meteo 오픈데이터 | 6시간 | 7일 |
| ECMWF AIFS | Open-Meteo | 6시간 | 7일 |
| NCEP GFS | Open-Meteo | 6시간 | 7일 |
| UKMO 10km | Open-Meteo | 6시간 | 7일 |
| 기상청 단기예보 | 공공데이터포털 | 3시간 | 약 5일 |
| 블렌드 | 위 모델에서 계산 | 모델 갱신 때마다 | 7일 |

- 변수: 기온, 체감온도, 강수량, 풍속, 풍향, 돌풍, 구름량, 날씨 코드.
- 골프장을 둘러싼 격자 중 고도가 가장 비슷한 육지 격자를 쓰고, 고도 차이만큼 기온을 보정한다(0.65°C/100 m). 모델 검증 때와 같은 방식이다.
- 원자료가 3·6시간 간격인 구간은 시간 단위로 보간한다. 강수는 구간 합계를 시간별로 고르게 나눈다.
- 최신 실행이 짧은 경우(ICON 06·18시 실행은 5일) 뒤쪽은 직전 실행으로 채운다.
- GFS와 AIFS는 돌풍 자료가 없다.
- **블렌드**: 기온·바람은 ICON·AIFS·IFS·UKMO 평균. 강수량은 중앙값. 비 유무는 다수결. 평균 강수량을 쓰면 약한 비가 과다 예보된다는 검증 결과를 반영했다.
- **기상청 단기예보**는 골프장의 격자(nx, ny)로 조회한다. 격자가 같은 골프장은 한 번만 호출한다. 이름 있는 488곳이 396격자에 모인다.

### 4.3 신뢰도

- [검증 결과](../research/model-verification/results/reliability_score.csv)의 모델 × 리드타임 점수를 고정값으로 싣는다.
- 배지 문구 예: "ICON · D+3 · ★★★★ (83점) · 기온 오차 1.3°C, 강수 적중 0.42 · 2026년 8~11월 전국 32개 지점 검증".
- 기상청 단기예보는 검증 자료가 없어 "검증 준비 중"으로 표시한다.

## 5. 구조

서버를 두지 않는다. 예보를 미리 계산해 정적 파일로 올리고, 앱은 그 파일만 읽는다.

```
[예약 작업, 3시간마다]                              [정적 호스팅 + CDN]
 모델 새 실행 확인 → 바뀐 모델만                     /app            웹 앱
 Open-Meteo · 기상청 호출 →                 →      /data/courses.json
 골프장별 JSON 생성 → 블렌드 계산                    /data/fc/{id}/{model}.json
 → 올리기 + 날짜별 보관                              /data/meta.json  모델별 최신 실행 시각
```

| 영역 | 선택 | 이유 |
|---|---|---|
| 웹 앱 | 프레임워크 없는 정적 페이지(`site/index.html`, `app.js`, `app.css`) | 빌드 단계 없이 바로 배포. 화면이 4개뿐이라 충분함. 화면이 늘면 4단계에서 프레임워크 도입을 다시 검토 |
| 차트 | 직접 그리는 SVG 또는 경량 차트 라이브러리 | 모바일 용량 |
| 검색 | 기기 안 검색, `es-hangul` | 520곳이라 서버가 필요 없음 |
| 지도 | Leaflet + OpenStreetMap 배경(위치 표시용) | 키 없이 동작. VWorld 위성 배경은 2단계 지도 날씨에서 도입 |
| 수집 작업 | Python, GitHub Actions 예약 실행 | 별도 서버 없이 시작. 지연이 문제 되면 Cloud Run으로 이동 |
| 호스팅 | GitHub Pages (저장소 공개) | 새 계정 없이 무료. 주소는 `https://songhyunwoong.github.io/golfweather/` |
| 키 보관 | GitHub Actions 시크릿 | 저장소에 키를 넣지 않음 |

### 호출량

- Open-Meteo: 무료 API는 지점 수·변수 수·모델 수를 곱해 호출량을 세므로, 전 골프장 1회 수집이 약 2,000회로 계산된다. 하루 한도(10,000회, IP 기준)에 걸린다. 8장 참고.
- 기상청: 396격자 × 하루 8회 ≈ 3,200요청/일. 개발계정 한도 10,000회/일 안이다.

### 예보 파일 형식

[개발 계획서 7장](PLAN.md#7-데이터-모델)의 예보 JSON을 쓴다. MVP에서는 `hourly`, `3hourly`, `daily`, `reliability`만 채운다.

## 6. 일정 (5주)

| 주 | 작업 | 끝났을 때 확인할 것 |
|---|---|---|
| 1 | 골프장 DB v2(검수 반영), 예보 수집 작업(Open-Meteo 5개 모델), 예보 JSON 생성 | 520곳 × 5모델 JSON이 만들어지고, 3곳을 골라 Open-Meteo 화면 값과 일치 |
| 2 | 기상청 단기예보 수집, 블렌드 계산, 예약 실행과 보관, 호스팅 설정 | 1시간마다 자동 갱신되고 실패 시 이전 파일이 유지됨 |
| 3 | 웹 앱 골격, 검색, 홈 | 초성 검색 시험 목록 100건 중 95건 이상 첫 결과 적중 |
| 4 | 골프장 상세(요약, 일별, 시간별, 모델 선택, 배지) | 휴대폰에서 상세 첫 화면 1.5초 안에 표시 |
| 5 | 모델 비교, 지도, 즐겨찾기, 정보 화면, 출처·면책, 베타 배포 | 아래 완료 기준 전체 |

1인 개발 기준이다. 검수가 1주차 안에 끝나지 않으면 v1로 개발을 진행하고 출시 전에 v2로 바꾼다.

## 7. 완료 기준

- [ ] 520곳 모두 상세 화면이 열리고 5개 모델과 블렌드 예보가 나온다.
- [ ] 기상청 단기예보가 격자가 있는 모든 골프장에서 나온다.
- [ ] 초성 검색 시험 목록 100건 중 95건 이상에서 첫 결과가 정답이다.
- [ ] 1시간/3시간 전환이 되고, 3시간 자료 구간이 구분되어 보인다.
- [ ] 모델 실행 공개 후 3시간 안에 반영된다.
- [ ] 수집 작업이 실패해도 앱은 이전 예보와 그 생성 시각을 보여준다.
- [ ] 휴대폰(4G)에서 상세 첫 화면이 1.5초 안에 뜬다.
- [ ] 모든 화면에 자료 출처가 있고, 상세 화면에 면책 문구가 있다.
- [ ] 예보 JSON이 날짜별로 보관되고 있다.
- [ ] 베타 사용자 10명이 실제 라운드 전에 써 보고 의견을 냈다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| **Open-Meteo 무료 API 한도 (실제로 발생)** | 2026-11-11 전 골프장 수집 2회째에 "Daily API request limit exceeded"로 막혔다. 한도가 IP 기준이라 GitHub Actions처럼 IP를 여럿이 나눠 쓰는 곳에서는 더 불안정하다. **대응: 예보 원천을 Open-Meteo 오픈데이터(AWS `s3://openmeteo`)로 바꾼다.** 모델 검증 때 쓴 방식이고 한도와 비용이 없다. 대안은 유료 구독($29/월) |
| Open-Meteo 무료 API는 비상업 전용 | 오픈데이터(CC BY 4.0)는 출처 표시만 하면 되므로 위 전환으로 함께 해결 |
| VWorld를 개발 환경(해외 클라우드)에서 확인할 수 없음 | 국내 브라우저에서 직접 확인. 안 되면 OSM 배경으로 출시하고 2단계에서 다시 봄 |
| GitHub Actions 예약 실행이 수십 분 늦을 수 있음 | 완료 기준을 "3시간 안"으로 잡음. 부족하면 Cloud Run 예약 작업으로 이동 |
| 기상청 API 장애·한도 | 격자 단위로 묶어 호출 수를 줄이고, 실패 시 이전 값 유지. 출시 전에 운영계정 전환 신청 |
| 골프장 DB 오류(이름, 중복) | 검수 반영이 출시 조건. 상세 화면에 오류 제보 주소 표시 |
| ICON이 7일차에 급락 | 배지로 드러냄(D+7 ★). 기본 모델을 리드타임별로 바꾸는 것은 3단계 |
